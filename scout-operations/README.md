# REACH Scout operations — closed-loop research (2026-10-28)

These files track **research coverage**, not human decisions or REACH publication.

* `monthly-triage.json`: append/update checkpoint entries keyed by `source_batch_id` plus `identity` (`doi:10...` or normalized `url:https://...`), after reading every raw `api-discoveries/batches/*.csv` record. Every input must eventually have a ledger record. Never delete completed cases or silently mark checks complete.
* `tools/build_coverage.py`: checks raw monthly batch checksums and row totals, reconciles every source record against the triage ledger, and emits `coverage.json`.
* `coverage.json`: monthly received, checked (terminal, evidenced), forwarded to Hub, already in REACH, untracked, and stale investigations. The GitHub Action refreshes it on monthly raw batch or ledger changes.
* `research-feedback.json`: initially empty; optional **public minimized operational hints** generated by an authorized reviewer from the Hub. Contains only opaque candidate IDs plus `suppress_reproposal`, `research_requested`, or metadata follow-up signals. No reviewer names, comments, native Smartsheet IDs, award details, or reviewer email addresses. This is intentionally *not* a human decision log. GitHub is public, so leave publishing disabled unless the user agrees to share these minimal signals.

**Ledger entry shape (example only, not an actual discovery):**

```json
{
  "source_batch_id": "YYYY-MM-DD-monthly-api-YYYY-MM-part-001",
  "identity": "doi:10.example/output",
  "cohort": "YYYY-MM",
  "status": "investigating",
  "updated_at": "YYYY-MM-DDTHH:MM:SSZ",
  "reach_snapshot": "",
  "evidence_url": ""
}
```

Allowed `status`: `awaiting_research`, `investigating`, `needs_more_research`, `already_in_reach`, `forwarded_to_hub`, `metadata_update_forwarded`, `no_action`.

Terminal status must have a verified public REACH snapshot (40-hex Git blob SHA or 64-hex SHA-256) and checked HTTPS evidence URL. An `already_in_reach` entry needs a specific `reach_match`. A forwarded entry needs the actual `scout_batch_path`. Confirmed exact duplicates without corrections do **not** go to the Discovery Hub.

Scout must check the source and current REACH catalog again when feedback or a new API version conflicts with earlier work. Do not treat absence of a feedback signal or a coverage counter as a review decision.

**Publication verification** is separate: the Hub's `REACH_Scout_Operations.gs` checks previously inserted Smartsheet candidates against *all* current public REACH index shards, using exact DOI/URL when possible and labeling title+award matches as **possible**, never confirmed. Nothing on this public repository grants permission to insert a source row.

**Safety:** no raw private review notes or sheet identifiers in any public GitHub file, no automated human approval, no direct Smartsheet write, no credential content.

## Metadata recovery and human referral

Scout records inaccessible Zenodo and other output metadata problems in `scout-operations/metadata-blockers.json`. Check up to five distinct metadata sources per investigation; do not count repeated refreshes. Wait at least seven days before one additional bounded retry, unless genuinely new source evidence warrants a documented exception. Stop afterward: mark `resolved`, `suppressed`, or `human_review` and continue other work.

Human referrals need substantive verification against full public REACH, output identity, public supporting evidence, and documented funding. Publish ONLY eligible investigated candidates in the standard `scout-discoveries/batches/` feed. Rationale must contain `Research escalation: Human Metadata Needed`, `Metadata recovery: Exhausted`, `Metadata missing:`, `Metadata checks:`, `Scout verification: Completed`, and `Scout classification: C NEEDS INVESTIGATION`. The Discovery Hub requires human completion before final Smartsheet insertion.

GitHub Actions validates blocker ledgers using `scout-operations/tools/validate_metadata_blockers.py`. The ledger is public: do not expose private review notes, staff identities, Smartsheet IDs, secrets, or restricted information.
