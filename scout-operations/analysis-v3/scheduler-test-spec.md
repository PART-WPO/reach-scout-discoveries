# Twenty proposed scheduler acceptance tests

INFERRED: These are specifications only. None is implemented or executed. All expected outcomes describe the proposed design in `ledger-design.md`.

| # | Situation | Expected outcome |
|---|---|---|
| 1 | INFERRED: The same DOI appears in monthly Crossref, historical Crossref and DataCite inputs. | One canonical method work key; all intake provenance retained. No repeated source investigation for the same method/input hash. |
| 2 | INFERRED: DOI spelling differs by case, `doi:` prefix or DOI-resolver URL. | Normalize the wrappers and case; preserve the DOI suffix and bind one identity. Reject malformed DOI text rather than guessing a replacement. |
| 3 | INFERRED: A completed award search is selected again with identical inputs. | Reuse the result; method attempts do not increase; no external search is repeated. Record a cache reuse only when the stored evidence is actually read. |
| 4 | INFERRED: The queue/report timestamp changes but the seed, sources and rules do not. | The method hash stays unchanged; queue rebuild does not reopen work. |
| 5 | INFERRED: A publisher returns HTTP 429 and Retry-After. | Mark that source blocked/rate-limited; retain partial evidence and the specified retry time; rotate. A due probe must show relevant changed availability before substantive work resumes. |
| 6 | INFERRED: Full text is inaccessible, while Crossref metadata succeeds. | Record the successful metadata observation; block only full-text scope. Do not infer an empty full-text result or repeat successful metadata checks. |
| 7 | INFERRED: A source returns malformed JSON, a checksum mismatch or an unexpected redirect. | Record a source-invalid blocker; never mark the method complete or claim absence. Preserve the prior valid result separately. |
| 8 | INFERRED: A REACH shard is unavailable during a negative duplicate check. | Hold novelty classification as unknown. Do not create a new-output proposal from a partial negative catalog scan. |
| 9 | INFERRED: Exact artifact primary URL and code/data type match an existing REACH record, whose title differs from the paper title. | Mark artifact as existing public output and skip a new-output proposal. Its different title does not undo the exact artifact identity. Retain seed-to-artifact relationship evidence. |
| 10 | INFERRED: A GitHub URL occurs only in a publication's supporting links, with no separate artifact primary-record match established. | Do not merge the software with the paper or claim the software already has its own REACH record. Resolve the full public primary-output identity first. |
| 11 | INFERRED: A DOI already occurs in the active Scout feed or pending inbox but private Hub import is unknown. | Reuse the public review unit; avoid another new-candidate draft. Private import, acceptance and REACH addition remain NOT_DETERMINED. |
| 12 | INFERRED: A final journal DOI has a verified preprint link and that work already exists in REACH as the preprint. | Preserve the existing UID; offer a metadata-update review if useful. No second publication record and no automatic retirement or insertion. |
| 13 | INFERRED: A preprint has no verified final version. | Keep it in a version watchlist/hold. Its related-artifact exploration can proceed separately without publishing the preprint as an official final article. |
| 14 | INFERRED: Two similar titles suggest a preprint/final relationship, but no explicit relation has been verified. | Mark version identity ambiguous; do not merge on title alone or assert a new distinct work. Route a bounded identity question. |
| 15 | INFERRED: A funded paper explicitly names a dataset as study output, and the dataset has no own award. | Create or reuse one artifact lead at `supporting output of a named paper`. Preserve its own funding as unverified. Offer policy-defined human eligibility review; neither discard it solely for a missing award nor assert same-DOI funding. |
| 16 | INFERRED: A paper cites generic third-party code or an older input dataset. | Record a citation/input relationship if useful. Do not call it a newly produced WPO artifact or promote it to same-DOI funding. Distinguish reuse from a study's supporting output. |
| 17 | INFERRED: The artifact's own official DOI metadata contains a verified WPO459 award and complete identity checks find no existing output or prior proposal. | Use `same-DOI award`; retain the full award and source hash. A genuinely eligible, metadata-complete lead may form one human-review proposal, never an automatic approval or catalog write. |
| 18 | INFERRED: A genuine new code/data lead is found in full text after an award search already completed; a new source changes only the link-scan evidence. | Add/deduplicate the artifact and reopen only affected downstream checks. Retain and reuse the unchanged award-search result. |
| 19 | INFERRED: Two workers simultaneously claim the same canonical DOI/method/hash; one crashes after a partial result. | One atomic lease wins. The other skips; after lease expiry, resume the incomplete attempt with an idempotency key. Do not double-count a completed request or publish twice. |
| 20 | INFERRED: Legacy notes have an aggregate terminal status but no method hashes, counts or evidence scope; human review is also unverified. | Import the note and aggregate status as context, put method status/count at NOT_DETERMINED/null, and queue at most one bounded baseline reconstruction. Do not turn missing history into zero attempts, completion or human approval. |
