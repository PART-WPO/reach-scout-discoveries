# Scout Discovery CSV publication: canonical draft format

**Authoritative from October 30, 2026 forward.** Scout no longer writes new batches directly into `scout-discoveries/batches/`. That directory is immutable after publication. New, unique 24-column drafts go into `scout-discoveries/inbox/` on main, and the existing GitHub Actions `Validate and Publish Scout Discovery Feed` workflow publishes them **only if all preflight checks pass**. Failed drafts do not change the published manifest or attribution metrics.

## Structured input rather than free-form rationale

Prepare a JSON array of research-supported candidates. `fields` uses the exact current 24-column CSV names **except** `Scout Discovery Rationale`, which is generated by the template. `provenance` holds structured research-route evidence. Omitted 24-column fields are written as blanks, never invented. Never provide `Candidate ID`, `Principal Investigator Email(s)` or private feedback.

**Example fixture only — not a real REACH candidate and never to be submitted:**

```json
{
  "candidates": [
    {
      "fields": {
        "Title": "Example research dataset",
        "DOI": "10.1234/example.dataset",
        "Output URL": "https://doi.org/10.1234/example.dataset",
        "Output Type": "3",
        "NOAA Award Number(s)": "NA23OAR4590137",
        "Publication Date": "2025-10-17",
        "Evidence URL": "https://example.org/doi-evidence",
        "Funding Evidence URL": "https://example.org/publisher-funding",
        "Existing REACH Match": "No match after complete checked REACH and Scout catalog",
        "Scout Confidence": "Medium",
        "Source Run ID": "REACH-SCOUT-EXAMPLE-ONLY"
      },
      "provenance": {
        "classification": "NEW CANDIDATE",
        "route": "API-seeded expansion",
        "seed_doi": "10.25923/t7t6-m677",
        "path_evidence": "https://example.org/publisher-funding",
        "intake_origin": "Historical DataCite API Backfill",
        "reach_snapshot": "aaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaa",
        "sources_checked": [
          "https://example.org/publisher-funding",
          "https://example.org/doi-evidence"
        ],
        "funding_basis": "Source acknowledgments independently identify the funded award; evidence is for demonstration only.",
        "related_outputs_checked": "Example source and candidate are different identities; full de-duplication required in real mission.",
        "notes": [
          "Reviewer question: Confirm public files and eligibility."
        ]
      }
    }
  ]
}
```

No sample values above are verified research; replace **every field** with real source-backed data for an actual mission. An example award or DOI must never become a real published candidate without evidence.

For an **independent discovery**, use `"route": "Independent discovery"`, include `"path_evidence": "https://..."` and `"discovery_method": "A substantive source search description..."`. Do **not** invent an API seed. For a **direct API** source, use `"route": "Direct API"` and DOI-specific source evidence. `"Metadata correction"` is not counted as a new output. If the actual origin is uncertain, use `"Unclassified"` and preserve evidence, not an invented route.

Accepted classifications are exactly `NEW CANDIDATE`, `POSSIBLE DUPLICATE`, `KNOWN DUPLICATE`, `NEEDS INVESTIGATION`, or `REACH METADATA UPDATE`.

For a monthly verified proposal, set `"intake_origin": "Monthly API"` and `"monthly_intake": "YYYY-MM"`, and provide a real REACH snapshot, sources checked, funding basis, and related outputs. For historical DataCite intake use **exactly** `"intake_origin": "Historical DataCite API Backfill"`; do not add parenthetical prose to the canonical field. Add context to `notes`.

## Prepare and preflight locally when Python execution is available

```bash
python scout-discoveries/tools/prepare_batch.py \
  --input-json /path/to/real-reviewed-metadata.json \
  --output scout-discoveries/inbox/2026-10-30-unique-new-run.csv

python scout-discoveries/tools/prepare_batch.py \
  --check scout-discoveries/inbox/2026-10-30-unique-new-run.csv

python -m unittest discover -s scout-discoveries/tools/tests -v
```

The builder refuses to overwrite an existing draft and validates the exact new CSV with the **same `build_manifest.inspect_batch` function** used by the production manifest workflow. In addition it requires canonical route/classification labels rather than accepting loose legacy prefixes. If local Python preflight is unavailable, do **not** claim a PASS: submit only a new inbox draft and let GitHub Actions perform the same gate **before any promotion**.

## Publication integrity and metrics

On a new inbox CSV commit, the GitHub Action:

1. Runs offline tests of the fixed-format writer, proof checks, and attribution computation.
2. Validates each changed inbox CSV against the exact 24-column schema, public-data limits and machine-readable provenance. It validates **all changed drafts before promoting any** in that run.
3. If **all** are valid, promotes exact UTF-8 bytes to a unique immutable file in `scout-discoveries/batches/`.
4. Runs `build_manifest.py` (the sole authorized writer of `scout-discoveries/manifest.json`) across *every* batch.
5. Re-reads the manifest and every batch and confirms SHA-256, row counts, source run IDs, and research route before rebuilding `scout-operations/discovery-origin-rollup.json`.
6. Commits newly published batches, manifest and reconciled attribution metrics together. If any gate fails, none of these published files are committed.

Research results, inbox drafts, manifest-published staging, private Hub import, reviewer approvals and public REACH additions remain **distinct states**. The rollup counts only manifest-published proposals; private human decisions and public REACH additions are `NOT_VERIFIED` unless separately observed. Do not manually edit a manifest, overwrite existing published batches or weaken the action to clear a research problem.

A subsequent correction to an unpublished draft should use a **new uniquely named inbox file** and a documented supersession trail; never silently overwrite an existing draft. Existing Hub reviewer choices and immutable manifest-listed batches always prevail.
